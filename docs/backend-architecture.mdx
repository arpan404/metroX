# Backend Core Architecture (V1.11)

- Documentation only; no API/schema/runtime behavior changes.

- `target_type`: `managed_llm_runtime`, `managed_agent_runtime`, `http`, `openai_compatible`, `agent_http`
- `provider_type`: `managed_llm_runtime`, `openai_compatible`

<a id="run-lifecycle-sequence"></a>
## Run Lifecycle Sequence

```mermaid
sequenceDiagram
    autonumber
    participant C as Client
    participant API as /v1 API
    participant DB as Database
    participant Q as RunQueue
    participant B as Background Task
    participant W as Redis Worker
    participant O as RunOrchestrator
    participant A as Target Adapter
    participant S as Streams SSE or WS

    C->>API: POST /v1/runs execute_now=true
    API->>DB: insert Run(status=queued)
    API->>DB: insert ConfigSnapshot and bind run.config_snapshot_id
    alt run_queue_enabled=true
        API->>Q: enqueue(run_id)
    else run_queue_enabled=false
        API->>B: add_task execute_run(run_id)
    end
    API-->>C: RunOut

    opt queue path
        Q->>W: pop run_id attempt
        W->>O: execute_run(run_id)
    end

    opt background path
        B->>O: execute_run(run_id)
    end

    O->>DB: mark running and AFKRunState running
    O->>DB: create or load BenchmarkSnapshot and AttackCases
    loop each unprocessed attack case
        O->>A: invoke target
        A-->>O: TargetResponse and AFK events
        O->>DB: insert Execution
        O->>DB: insert Detection and DetectionVotes
        O->>DB: insert ProbabilisticLabel
        O->>DB: insert ExecutionCost and update run cost gate
        O->>DB: log progress and AFKRunState checkpoints
        alt budget breach and abort_on_cost_breach
            O->>DB: mark run interrupted and checkpoint
            O-->>C: terminal status interrupted
        end
    end

    O->>DB: rebuild cost aggregate
    O->>DB: rebuild features and clusters
    O->>DB: build risk models and advanced analytics
    O->>DB: build scorecard and drift
    O->>DB: mark run completed and log run_completed

    C->>API: GET /v1/runs/{id}/events or WS
    API->>S: stream RunEvent rows until terminal status
    S-->>C: event stream and end signal
```

<a id="security-and-credential-lifecycle"></a>
## Security and Credential Lifecycle

```mermaid
sequenceDiagram
    autonumber
    participant U as API User
    participant API as Security and Credential APIs
    participant DB as Database
    participant C as SecretCipher

    U->>API: POST /v1/security/keys (create key)
    API->>DB: insert secret_keys status active or retiring
    API->>DB: insert secret_key_events action=create

    U->>API: POST /v1/security/keys/{id}/activate
    API->>DB: mark previous active keys as retiring
    API->>DB: mark selected key active
    API->>DB: insert secret_key_events action=activate

    U->>API: POST /v1/providers/credentials
    API->>C: encrypt(api_key)
    alt no active key
        C-->>API: ValueError fail fast
        API-->>U: 400 no active key
    else active key present
        C-->>API: dbk:key_id:version:ciphertext
        API->>DB: insert provider_credentials
        API->>DB: insert secret_access_audits action=create
    end

    U->>API: POST /v1/security/keys/{id}/reencrypt-credentials
    API->>C: decrypt each credential
    API->>C: encrypt with active key
    API->>DB: update provider_credentials key_version and encrypted_secret
    API->>DB: insert secret_key_events action=reencrypt_credentials

    U->>API: POST /v1/security/keys/{id}/retire
    alt key is active
        API-->>U: 400 cannot retire active key
    else non-active key
        API->>DB: mark key retired
        API->>DB: insert secret_key_events action=retire
    end

    U->>API: GET credential or validate via credential_id
    API->>C: decrypt for use
    API->>DB: insert secret_access_audits success or failure
```

<a id="scenario-traces-for-validation"></a>
## Scenario Traces for Validation

1. Standard run completes end-to-end.
- Create session, profile, run with `execute_now=true`.
- Run transitions: `queued -> running -> completed`.
- Orchestrator emits benchmark, progress, analytics, scorecard, drift, completed events.
- Scorecard, risk, features, detector votes, cost summary, and report endpoints return populated payloads.

2. Cost gate breach then resume without duplicate execution.
- Run executes with low budget and `abort_on_cost_breach=true`.
- Status transitions to `interrupted` with checkpoint persisted in `AFKRunState`.
- Resume requeues run, skips already processed `attack_case_id` values, and reaches `completed`.
- Execution count equals `total_attacks` after resume.

3. Credential validation with active key and auditable access.
- Key create and activate performed before credential encryption/decryption.
- Provider credential stored as DB-wrapped ciphertext format `dbk:key_id:version:payload`.
- Validation with `credential_id` decrypts key via `SecretCipher` and writes `SecretAccessAudit` records.
- Key lifecycle operations emit `SecretKeyEvent` entries.

4. High disagreement or uncertainty adjudication candidate.
- Multiple detector votes are fused into final detection.
- `disagreement_score` and `uncertainty` computed per execution.
- If threshold exceeded, execution marked as adjudication candidate for review.
- Manual adjudication endpoint can override failure flags and increase confidence.
